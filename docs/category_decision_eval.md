측정일 2026-10-30. 재현: `tools/exp_decision_cls/README.md`.
이슈 #145 결정(10/19)의 후속이다. 결정은 "Plaid 방식 분류 흐름 끝에 jev 또는 6luna 의 `/decisions` 를 붙이고,
1등 신뢰도가 기준값 이하면 미정으로 두고 1등을 추천한다" 였다. 남은 두 가지, **어느 모델인지와 기준값**을 쟀다.

## 그래서 무엇을 고를 것인가 (권고)

**1. 잔여분에서는 어느 모델도 정밀도 95%로 자동 확정을 하지 못한다.**
J 의 7.3%는 1건씩 보낼 때만 나오고 배치(N=30)에서는 0 이다.
9/23 의 결론("모델은 잔여분을 없애 주지 않는다", `category_classifier_vs_embedding.md`)과 같은 방향이다.
모델의 자리는 **추천**이다. 자동 확정은 하지 않는다(3-1, 임계값 분석).

**2. 추천 품질 · 쉬운 몫 · 재현성은 L 이 낫거나 같다 → L(Luna 6 `/decisions`)을 권한다.**
- 미정 건 추천 적중이 res 에서 0.396 대 0.325 다.
- kwonly top1 이 0.67 대 0.62, repo 키워드 미적중 top1 이 0.90 대 0.77 이다.
- 반복 흔들림이 0% 대 8%이고, 지연도 L 이 짧다.
- J 가 나은 것은 잔여분에서 신뢰도가 정확도를 따라간다는 점과 단가다. 비용은 둘 다 1,000건당 0.3달러 이하라 판단 요소가 아니다.

**3. 1등 신뢰도 하나로는 자동 확정 기준을 잡을 수 없다.**
- L 의 신뢰도는 잔여분에서 과신한다. 1.0 이어도 정밀도가 75%이고, 기타를 빼도 82%다.
- 쉬운 몫에서 잡은 기준값을 그대로 쓰면 잔여분이 대량으로 틀린 채 통과한다.

**3-1. L 은 기타를 뺀 선택지 + 예/아니오 질문(NK)으로 부르고, 자동 확정 없이 top-3 를 추천만 한다(10/31 결정, PR #196 리뷰).**
- 모든 답을 되묻기로 보낸다. 되묻기 화면에는 top-3(`suggestedCategories`)를 추천으로 띄우고, 전체 목록과 `기타` 를 바로 고를 수 있게 둔다.
- 거절이면 추천 없이 전체 목록을 보여 준다.
- 확정하지 않는 이유: 가장 엄격한 기준(예 ≥ 0.99 그리고 1등 신뢰도 = 1.00)에서도 잔여분 정밀도가 91%(하한 82%)다. 서비스는 신뢰도가 먼저라 이 수준으로는 확정하지 않는다.
- 예상: 잔여분 top-3 적중은 0.63 이다.
- 예/아니오 확률은 되묻기 화면에서 "AI 가 추론함"과 "판단하지 못함"을 나눌 때 쓸 수 있다(리뷰 제안, 후속).
- 실카드에서 사용자가 고른 답으로 정밀도를 다시 재고, 충분히 높으면 자동 확정을 다시 검토한다.

**4. B10 호출은 업로드의 미분류를 30개 안팎으로 묶어 보낸다.**
- 100개 묶음은 L 토큰이 제곱으로 늘고 J 는 한도를 넘는다.
- 1건씩 병렬 호출도 지연(p95 0.6초)상 가능하다. 배치와 답이 4분의 1 다르니 한 방식으로 고정한다.

## 임계값 분석 — 자동 확정 기준 (L · NK)

**10/31 결정: 자동 확정은 하지 않는다(3-1).** 아래는 자동 확정을 검토하며 잰 기록이다. 실카드로 다시 잴 때 출발점으로 쓴다.

검토한 운영 흐름은 이렇다.
- 기준을 넘으면 카테고리를 확정한다.
- 넘지 못하면 되묻기 화면으로 보낸다. 30개를 다 보여 주는 대신 모델의 top-3 를 추천으로 띄우고, 전체 목록에서도 고를 수 있게 한다.

그래서 정할 것은 자동 확정 규칙 "예 ≥ k 그리고 1등 신뢰도 ≥ t" 의 두 값이다.
재현: `python tools/exp_decision_cls/threshold_grid.py`(test), `--split dev`(dev), `--errors 0.99 1.0`(오답 목록).

res test 505건 격자 일부다. 칸은 확정 비율 / 정밀도 (Wilson 95% 하한) · 판정 전이 / →가능.

| 예 ≥ k \ 1등 ≥ t | 0.5 | 0.9 | 0.99 | 1.00 |
|---|---|---|---|---|
| 0.5 | 48% / 67% (61%) · 39/2 | 37% / 73% (66%) · 23/2 | 24% / 80% (72%) · 9/0 | 16% / 88% (79%) · 5/0 |
| 0.95 | 38% / 71% (65%) · 29/1 | 30% / 75% (67%) · 19/1 | 21% / 82% (74%) · 9/0 | 15% / 90% (81%) · 5/0 |
| 0.99 | 31% / 74% (67%) · 21/1 | 25% / 78% (70%) · 14/1 | 18% / 86% (78%) · 7/0 | **13% / 91% (82%) · 4/0** |

**가장 엄격한 칸: 예 ≥ 0.99 그리고 1등 신뢰도 = 1.00.**
L 은 신뢰도를 소수 둘째 자리로 주므로, 1.00 은 반올림해서 1.00 이 된 값이다.

| 셋 | 자동 확정 | 정밀도 (하한) | 판정 전이 / →가능 | 되묻기 건의 top-3 적중 |
|---|---|---|---|---|
| res test | 13% (67건) | 91% (82%) | 4 / 0 | 0.58 |
| res dev (임계값을 고를 때 쓰지 않은 95건) | 11% (10건) | 100% (72%) | 0 / 0 | 0.58 |
| kwonly | 26% | 92% (76%) | 0 / 0 | 0.80 |
| repo | 47% | 95% (87%) | 3 / 1 | 0.88 |
| repo 키워드룰 미적중 | 16% (8건) | 88% (53%) | 1 / 0 | 0.86 |

- **어떤 조합도 res 에서 라벨 기준 정밀도 95%에 닿지 않는다.** 이 칸이 가장 엄격한 쪽에 가깝고, 한 단계만 풀어도 정밀도가 떨어진다.
  - 예 ≥ 0.99 · 1등 ≥ 0.99: 18% / 86%
  - 예 ≥ 0.5 · 1등 ≥ 0.9: 37% / 73%
- 예/아니오는 1등 신뢰도만 쓸 때보다 오답을 조금 더 거른다.
  - 1등 = 1.00 만 쓰면 res 16% / 88%이고, dev 에서는 14건 중 오답 2건이다.
  - 예 ≥ 0.99 를 더하면 res 13% / 91%, dev 10/10 이다.
- 이 칸의 res 오답 6건을 네이버 지도로 확인했다. 대부분 규칙이나 라벨 문제다.
  - 등록 업종 이상 3건(모델 답이 맞다): `김준호의대단한갈비인`[서점] → 음식점, `남이불고기`[정육점] → 음식점, `퍼닛PC울산점`[컴퓨터 수리] → 여가(PC방)
  - 규칙 경계 2건: `이오석유` → 차량(정답 수도광열, 주유소도 같이 해 차량이 자연스럽다), `YG힐링안마원` → 미용(정답 의료)
  - 모델 오답 1건: `홍리뷰티여수점`[슈퍼마켓] → 미용
  - 모델 오답만 세면 66/67 = 98.5%(하한 92%)다. 다만 67건뿐이고, 라벨을 사후에 고쳐 센 수치다.
  - 경비로 잘못 통과(→가능)는 0건이다. 판정이 바뀐 4건은 모두 확인필요나 불가 쪽이다.
- kwonly 오답 2건도 석유(→ 차량)와 안마원(→ 미용)이다.
- repo 오답 3건은 셋 다 경계 사례다.
  - 판정 평가셋 기대값과의 경계 2건: 컴퓨터 수리센터 기타 → 수리비, 애플코리아 사무용품 → 전자기기. 컴퓨터 수리센터 1건이 →가능이다.
  - 슈퍼마켓 충돌 1건: 키워드룰과 매핑표가 서로 다르게 본다.
- **정밀도를 올릴 곳은 임계값이 아니라 규칙이다.** 아래 셋을 정리하면 남은 오답 대부분이 사라진다. 키워드룰로 잡으면 모델까지 오지도 않는다.
  - 석유 · 가스: 수도광열인지 차량인지
  - 안마원: 의료인지 미용인지
  - 슈퍼마켓: 매핑표는 편의점, 키워드룰은 생활용품
- 되묻기로 가는 res 의 약 40%는 정답이 top-3 밖이다. 되묻기 화면에서 전체 목록과 `기타` 를 바로 고를 수 있어야 한다.
- 표본이 작다. res 자동 확정이 67건이라 정밀도 하한이 82%다.
  - L 은 같은 입력에 같은 값을 주므로, 같은 가맹점이 업로드마다 다른 추천을 받지는 않는다.
- 임계값은 test 를 보고 골랐다. dev 는 이 결정에 쓰지 않은 셋이지만 95건이라 확인하는 정도다.

## 이 수치를 그대로 쓰면 안 되는 이유

- **라벨은 상권정보 등록 업종을 매핑표 초안으로 옮긴 것이다.**
  - res test 에서 두 팔이 같은 답인데 라벨과 다른 152건 중 60건을 사람이 봤다. 7건은 라벨 쪽이 틀렸다(교육업체가 `서점` 으로 등록 5, 부동산이 `문구` 로 등록 1, 올리브영이 `기타` 매핑 1). 약 4건은 애매하고, 나머지는 이름에 업종 단서가 없는 경우다.
  - 7건을 고쳐 다시 채점하면 top1 이 J 0.386 · L 0.410 이 되고 auto@p95 는 그대로다. 두 팔이 같은 답이라 비교는 바뀌지 않는다.
- 입력은 실카드 표기가 아니라 상호 + 지점명을 20바이트로 자른 근사다.
- res 는 카테고리별 균등 표본이라 실제 미분류 분포가 아니다. 실제 분포에서는 평균 정확도가 달라진다.
- 온라인 · 해외 몫은 repo 137건(키워드 미적중 51건)뿐이라 표본이 작다.
- auto@p95 는 기준값이 계단처럼 바뀌어 표본에 민감하다. repo 의 차이 구간은 폭이 1 이 넘는다.
- 게이트웨이 단가가 아니라 공시가로 환산한 비용이다.
- 모델 버전이 바뀌면 다시 재야 한다. J 는 같은 요청에도 답이 흔들린다.
