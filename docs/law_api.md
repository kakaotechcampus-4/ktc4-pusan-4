# 국가법령정보 OPEN API 사용법

법제처 국가법령정보 공동활용(`open.law.go.kr`)이 제공하는 OPEN API 정리.
법령 동기화 파이프라인(CONTEXT.md §11)과 RAG 색인의 유일한 원문 소스다.

- 공식 가이드: <https://open.law.go.kr/LSO/openApi/guideList.do>
- 활용방법: <https://open.law.go.kr/LSO/openApi/openApiManual.do>
- 문의: 02-2109-6446

---

## 1. 엔드포인트

엔드포인트는 두 개뿐이고, `target` 값으로 무엇을 조회할지 정한다.

| 구분 | URL |
|---|---|
| **목록 조회** | `https://www.law.go.kr/DRF/lawSearch.do` |
| **본문 조회** | `https://www.law.go.kr/DRF/lawService.do` |

호스트가 `open.law.go.kr`(포털)이 아니라 **`www.law.go.kr`(API)** 인 점에 주의.

### 공통 필수 파라미터

| 변수 | 값 | 설명 |
|---|---|---|
| `OC` | string (필수) | API 인증키. `open.law.go.kr` 가입 후 [API인증키관리](https://open.law.go.kr/LSO/usr/usrOcInfoMod.do)에서 확인 |
| `target` | string (필수) | 서비스 대상 (아래 표) |
| `type` | char (필수) | `HTML` / `XML` / `JSON`. 생략 시 기본값 `XML` |

> **`OC=test`가 공개로 동작한다.** 발급 키 없이 개발·테스트가 가능하다.
> 운영 코드에서는 반드시 발급받은 OC를 환경변수로 주입할 것.

### 호출 흐름

```
lawSearch.do (목록)
  → 응답의 [일련번호] 또는 [상세링크] 획득
    → lawService.do (본문)
```

목록 응답의 `법령상세링크` 필드는 이미 `/DRF/lawService.do?OC=...&target=...&MST=...` 형태로
완성되어 있으므로 `https://www.law.go.kr` 를 앞에 붙여 그대로 호출하면 된다.

## 2. target 목록 (프로젝트 관련분)

| target | 대상 | 목록 | 본문 | 비고 |
|---|---|---|---|---|
| `eflaw` | 현행법령 (**시행일** 기준) | ✅ | ✅ | 조문 단위 조회(`JO`) 지원 |
| `law` | 현행법령 (**공포일** 기준) | ✅ | ✅ | |
| `admrul` | 행정규칙 (훈령·예규·고시·지침) | ✅ | ✅ | `modYd`로 증분 동기화 가능 |
| `prec` | 판례 | ✅ | ✅ | `datSrcNm=국세법령정보시스템` 필터 가능 |
| `expc` | 법령해석례 (법제처) | ✅ | ✅ | |
| `ttSpecialDecc` | **조세심판원 심판례** | ✅ | ✅ | 특별행정심판 재결례 |
| `ntsCgmExpc` | 국세청 1차 법령해석 | ✅ | ❌ | **목록만 수집** (§9) |

그 외 `lsDelegated`(위임법령), `lsStmd*`(체계도), `lsHst*`(연혁), `oldAndNew*`(신구법),
`thdCmp*`(3단 비교), `detc`(헌재결정례), `decc`(행정심판례) 등이 있다. 전체는 가이드 목록 참조.

> ⚠️ **`ntsCgmExpc`는 본문 조회 API가 없다.** 목록 응답의 `법령해석상세링크`가
> `https://taxlaw.nts.go.kr/...` 라는 **외부 주소**다.
> **본문은 수집하지 않는다** — 이유와 범위는 §9 참조.

가이드 전수 확인 결과, 중앙부처 1차 해석 제공기관 39곳 중 본문(Info) API가 없는 곳은
**기획재정부(`cgmExpcMoef`)와 국세청(`cgmExpcNts`) 딱 2곳**이다. 관세청조차 본문 API가 있다.

## 3. 목록 조회 (`lawSearch.do`)

### 공통 파라미터

| 변수 | 값 | 설명 |

| `query` | string | 검색어. 정확 검색은 `query="자동차"` 처럼 따옴표 |
| `search` | int | 검색범위. `1`=제목(기본), **`2`=본문검색** |
| `display` | int | 결과 개수. 기본 20, **최대 100** |
| `page` | int | 페이지 번호 (기본 1) |
| `sort` | string | 정렬옵션 (target별 상이) |

| `popYn` | string | 상세화면 팝업 여부 (`Y`) |

## 4. 본문 조회 (`lawService.do`)

| target | 식별자 파라미터 |
|---|---|
| `eflaw` | `ID`(법령ID) **또는** `MST`(법령 마스터번호=`lsi_seq`) + `efYd`(시행일자, MST 사용 시 필수) |
| `law` | `ID` 또는 `MST` |
| `admrul` | `ID`(일련번호) / `LID`(행정규칙ID) / `LM`(정확한 행정규칙명) |
| `prec` | `ID`(판례 일련번호, 필수) / `LM` |
| `expc` | `ID`(해석례 일련번호, 필수) / `LM` |
| `ttSpecialDecc` | `ID`(재결례 일련번호, 필수) / `LM` / `fields`(응답항목 선택, HTML 제외) |

### 법령 본문 전용 파라미터

| 변수 | 설명 |
|---|---|
| **`JO`** | **조번호 단위 조회.** 6자리 = 조번호(4) + 조가지번호(2). `000200`=제2조, `001002`=제10조의2. 생략 시 전체 조문 |
| `chrClsCd` | `010202` 한글(기본) / `010201` 원문 |

> `JO` 파라미터 덕분에 **조문 1개 단위 청킹**(CONTEXT.md §11)을 API 레벨에서 그대로 뜰 수 있다.
> ⚠️ 단, 단서(`다만 ~`)는 `조문내용`/`항내용` 안에 그대로 들어있으므로 청킹 시 잘리지 않게 할 것.

### 판례 본문 제약

`prec` 본문 조회에서 **국세청 출처 판례(`datSrcNm=국세법령정보시스템`, 49,950건)는 본문을 받을 수 없다.**
가이드에는 "HTML만 가능"이라고 되어 있으나 실제 동작은 다음과 같다(검증함):

```
lawService.do?target=prec&ID=613735&type=JSON
  → {"Law": "일치하는 판례가 없습니다."}
lawService.do?target=prec&ID=613735&type=HTML
  → law.go.kr/LSW/precInfoP.do 로 가는 JS 리다이렉트 껍데기 (본문 없음)
```

**목록(메타데이터)은 정상 수집된다.** 대법원 등 그 외 출처 판례는 JSON 본문이 정상적으로 나온다.

## 6. 검증된 호출 예시

아래는 `OC=test`로 실제 응답을 확인한 요청이다.

```bash
# 소득세법 목록 (JSON)
curl "https://www.law.go.kr/DRF/lawSearch.do?OC=test&target=eflaw&type=JSON&query=소득세법&display=3"

# 소득세법 제33조 본문
curl "https://www.law.go.kr/DRF/lawService.do?OC=test&target=law&ID=001565&JO=003300&type=JSON"

# 법제처 법령해석례 - '필요경비'
curl "https://www.law.go.kr/DRF/lawSearch.do?OC=test&target=expc&type=JSON&query=필요경비&display=2"

# 조세심판원 심판례 본문검색 - '필요경비'
curl "https://www.law.go.kr/DRF/lawSearch.do?OC=test&target=ttSpecialDecc&type=JSON&search=2&query=필요경비&display=2"

# 국세청 1차 법령해석 본문검색 - '필요경비' (총 2,459건)
curl "https://www.law.go.kr/DRF/lawSearch.do?OC=test&target=ntsCgmExpc&type=JSON&search=2&query=필요경비&display=2"

# 행정규칙 - 수정일자 기간으로 증분 수집
curl "https://www.law.go.kr/DRF/lawSearch.do?OC=test&target=admrul&type=JSON&modYd=20260101~20260131&display=100"
```

응답 예시 (`ttSpecialDecc` 목록):

```json
{"Decc": {"decc": [{
  "id": "1",
  "재결청": "조세심판원",
  "특별행정심판재결례일련번호": "50516",
  "재결구분코드": "429150",
  "청구번호": "조심2014서0879",
  "의결일자": "2014.12.18",
  "행정심판재결례상세링크": "/DRF/lawService.do?OC=test&target=ttSpecialDecc&ID=50516&type=HTML"
}]}}
```

## 7. 주의사항 (실제로 걸린 것들)

| 항목 | 내용 |
|---|---|
| **HEAD 요청 404** | `lawSearch.do`에 HEAD를 보내면 `404`가 온다. 헬스체크·존재확인을 HEAD로 짜면 안 된다. **GET만 사용** |
| **인코딩 이원화** | API 응답(JSON/XML)은 **UTF-8**. 반면 `open.law.go.kr` 가이드 **페이지는 EUC-KR(cp949)**. 가이드를 스크래핑할 일이 있으면 `cp949`로 디코딩 |
| **가이드 페이지는 JS 렌더링** | 가이드 상세는 `guideResult.do`에 `htmlName`을 **POST**해야 나온다. GET 링크가 없다 (`<a href="#" onclick="openApiGuide('lsEfYdListGuide')">`) |
| **`display` 상한 100** | 그 이상은 `page`로 페이징. 전량 수집 시 총건수(`totalCnt`) 기준 루프 |
| **`ntsCgmExpc` 본문 없음** | 목록만 제공. 본문은 수집 대상 아님 (§9) |
| **국세청 출처 판례 본문 없음** | JSON은 "없습니다" 응답, HTML은 리다이렉트 껍데기. 목록만 수집 (§9) |
| **호출 한도** | 매뉴얼에 쿼터 명시 없음(미확인). 대량 수집 시 간격을 두고, IP 접속이력 페이지로 모니터링 |
| **문서 URL이 http** | 가이드의 샘플 URL이 전부 `http://`다. **`https://`로 호출할 것** |

### 파서를 조용히 깨뜨리는 것들 (2026-09-08 구현 중 실측)

전부 예외 없이 지나가면서 데이터만 사라지는 종류다. 순서대로 겪었다.

| 현상 | 실측 | 대응 |
|---|---|---|
| **결과 1건이면 배열 대신 객체** | `조문단위`·`항`·`호`·`목`·`admrul` 전부 | `as_list()` 로 전면 정규화 |
| **`목내용`이 중첩 리스트** | 소득세법 27건 | `_flat()` 재귀 평탄화. 문자열만 가정하면 `AttributeError` |
| **`호번호`가 가지번호를 빠뜨림** | `2의2`가 `2.`로 온다. 소득세법에서 `statute_id` 11건 충돌 | `호내용` 앞의 번호를 파싱 |
| **항번호 없는 항에도 호가 달림** | 제12조(비과세소득) 3,025자가 통째로 사라질 뻔 | 항번호 없으면 제1항으로 처리 |
| **목록 필드명 ≠ 본문 필드명** | 목록 `판례일련번호` vs 본문 `판례정보일련번호`, 목록 `회신일자` vs 본문 `해석일자` | 파서를 목록/본문 별도로 |
| **날짜 형식 이원화** | 목록 `2014.12.18`, 본문 `20141218` | 숫자만 남기고 파싱 |
| **심판례 본문의 빈 필드** | `청구번호`·`사건번호`·`처분청`·`처분일자`가 전부 `""` | **목록 응답을 들고 있다가 본문과 머지** |
| **`선고` 필드에 문자열 `"null"`** | 판례 목록 | 쓰지 않는다 |
| **행정규칙명이 유일하지 않음** | `업무용승용차 운행기록 방법에 관한 고시`가 소득세법·법인세법 근거 둘 다 현행 | `statute_id`에 `행정규칙ID` 포함 |
| **본문에 HTML 태그 잔존** | 경비율 고시에 `<img>` 38개, 판례에 `<br/>` | 태그명을 열거해 제거. `<[^>]*>`로 지우면 `<개정 2009.12.31>`이 날아간다 |
| **껍데기 조문** | `제8조`(이동), `제10조 (삭제 2009. 5. 22.)`, 편장절 제목(`조문여부=전문`, 소득세법 67개) | 행을 만들지 않는다 |
| **미신청 API는 HTML을 준다** | JSON 파싱 에러로 나타난다. 재시도해도 소용없다 | 응답 첫 글자가 `<`면 별도 처리 |

## 8. 파이프라인에서의 사용 (CONTEXT.md §11 연계)

```
[일 1회 03:00 KST]
  법령·행정규칙   → target=law / admrul
                    전량 목록 조회 → 공포번호 + 조문 해시 비교 (수백 건)
                    admrul은 modYd 기간검색으로 증분 축소 가능
  판례·심판례·해석 → target=prec / ttSpecialDecc / expc
                    신규 생산분만 증분 (prncYd / 의결일자 / explYd 기준)
  국세청 법령해석   → target=ntsCgmExpc — 목록(메타)만. 본문 없음 (§9)
  변경 감지 → statute_version 새 행 (append-only) → 조건부 재색인
```

- **조문 단위 청킹**은 `eflaw` + `JO`로 직접 뜨거나, 전체 본문 응답의 `조문단위` 배열을 순회.
- **변경 감지**는 본문 응답의 `조문변경여부`(`Y`)를 1차 신호로 쓸 수 있으나,
  최종 판단은 자체 조문 해시 비교로 한다(API 필드 신뢰도 미검증).
- **`lsDelegated`**(위임법령 조회) API로 "…대통령령으로 정하는" 류의 링크를
  조항호목 단위로 해석할 수 있다. 법 → 시행령 연결 자동화에 사용 검토.

## 9. 수집 범위와 한계 — 국세청 자료

### 결정: 법령 API로 받을 수 있는 것만 받는다

국세청 자료 중 **본문**은 법제처 OPEN API로 제공되지 않는다.
국세법령정보시스템(`taxlaw.nts.go.kr`)에는 본문이 존재하지만, **공식 오픈API가 없다.**
사이트 화면이 내부적으로 쓰는 엔드포인트를 역이용하는 방법밖에 없어서 **사용하지 않기로 했다.**

**이유**

- 문서화된 규격이 아니라 계약이 없다. 예고 없이 바뀌거나 막힐 수 있다.
- 정부 사이트를 대량 조회하는 형태가 된다.
- 이용조건(공공누리 유형 등)을 확인하지 못했다.

### 그래서 빠지는 것

| 대상 | 건수 | 목록/메타 | 본문 |
|---|---|---|---|
| 국세청 1차 법령해석 (`ntsCgmExpc`) | 136,514 | ✅ 수집 | ❌ 없음 |
| 국세청 출처 판례 (`prec` + `datSrcNm=국세법령정보시스템`) | 49,950 | ✅ 수집 | ❌ 없음 |

**목록은 계속 수집한다.** 안건명·안건번호·해석일자·기관·상세링크가 들어있어
검색과 "관련 자료가 있다"는 표시, 원문 링크 제공까지는 가능하다.
**RAG 색인 대상이 아닐 뿐이다.**

### 대신 확보되는 세무 근거

본문까지 정상적으로 들어오는 것들로 커버한다.

| 대상 | target | 본문 필드 |
|---|---|---|
| 소득세법·시행령 등 법령 | `eflaw` / `law` | 조문·항·호·목 (조문 단위) |
| 행정규칙 (기본통칙·고시) | `admrul` | 조문 |
| 법제처 법령해석례 | `expc` | `질의요지` · `회답` · `이유` |
| **조세심판원 심판례** | `ttSpecialDecc` | `재결요지` · `주문` · `이유` · `관련법령` |
| 대법원 판례 | `prec` | `판시사항` · `판결요지` · `판례내용` · `참조조문` |

특히 **조세심판원 심판례(`ttSpecialDecc`)가 법령 API로 본문까지 완전히 들어온다.**
`이유` 필드에 판단 논거가 통째로 담겨 있어(샘플 7,633자), 국세청 해석 공백을 상당 부분 메운다.

### 나중에 다시 볼 때

국세청/기획재정부 본문 API는 **법제처가 열어주면** 바로 해결된다
(다른 37개 부처는 이미 `cgmExpc<부처>InfoGuide`로 제공 중).
주기적으로 [가이드 목록](https://open.law.go.kr/LSO/openApi/guideList.do)에
`cgmExpcNtsInfoGuide`가 생겼는지 확인할 것.
