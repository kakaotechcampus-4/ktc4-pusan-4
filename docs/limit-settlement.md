# 연간 한도 집계 결정사항

G6는 건별 판정 중에 한도 버킷과 대상 금액만 태그한다. 인정 금액은 같은 사용자,
귀속연도, 버킷의 전체 거래를 모은 뒤 별도 집계 단계에서 계산한다.

## 배분 순서

1. 승인일 오름차순
2. 승인일이 같으면 판정 UUID 오름차순

입력 목록의 순서와 무관하게 같은 결과가 나오도록 위 순서를 항상 적용한다.

이 순서는 법 근거가 없는 내부 계산이다. 소득세법 §35 3항은 연간 총액으로만 정하고, 어느 거래를
초과분으로 볼지 정하지 않는다. 그래서 거래별 `allowed_amount`는 API 로 내보내지 않는다(#15).
밖으로 나가는 값은 순서와 관계없는 것뿐이다.

- `year` 요약: 한도 인정액 합
- `batchId` 요약: `finalAmount` 합
- `limits`: 과세연도별 한도 전 합계와 초과액
- 내보내기: 한도를 넘은 해의 접대비 행은 `allowedAmount` 를 비운다

## 상태 전이

확정 전환은 아직 구현하지 않았다(`finalizeEntries` 를 부르는 곳이 없다). 발표 이후로 미룬다(#15).
아래는 그때의 규칙이다.


- 재계산 결과는 항상 `잠정`으로 저장한다.
- 당해연도 수입금액이 확인되고, 미응답 질문과 검토 대기 판정이 모두 없을 때만
  `확정`으로 전환한다.
- 답변이나 정정으로 다시 계산하면 기존 확정 결과도 `잠정`으로 되돌린다.
- 재계산 대상에서 빠진 항목은 해당 버킷에서 제거한다.
