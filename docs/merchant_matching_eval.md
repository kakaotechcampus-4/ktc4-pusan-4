# 카테고리 분류: 가맹점 데이터셋 매칭(Plaid 방식) 대리 평가

측정일 2026-09-28. 재현: `tools/exp_merchant_match/README.md`.
[분류기 vs 임베딩 비교](category_classifier_vs_embedding.md)의 후속이다. 3주차 멘토 리뷰(PR #50)에서
"이름만 보고 맞히는 모델을 메인으로 쓰기보다 가맹점 데이터셋과 사용자 이력을 먼저 쓰고 모델은 보조로"라는
방향을 받아, 상권정보를 가맹점 데이터셋으로 쓰는 매칭 방식을 측정했다.

## 방식

```
카드 문자열 → PG·플랫폼 블록 → 키워드룰 → 상권정보 매칭
   ├ 같은 이름 가게들의 최다 카테고리 비율 ≥ 0.9 → 자동 확정
   └ 그 밖(비율 미달·매칭 실패) → 후보를 보여주고 사용자 선택 → 개인 사전(USER_FACT)
```

- 매칭: 정규화 키 정확 일치 → (20바이트 절단 시) 접두 확장 → 최장 접두
- 예측: 매칭된 가게들의 소분류를 우리 32 카테고리로 옮긴 뒤 최다 카테고리 (`mapping_940909.csv`)

## 평가 방법 — 대리 평가

실카드 원본이 없어 상권정보 277만 행 자체를 인덱스로 쓰고, 같은 데이터에서 2만 행을 카드 문자열처럼 변형해 조회했다.

- 문자열: 상호명+지점명을 붙여 **EUC-KR 20바이트로 절단**(실카드 표기에 가장 가까움)
- 시나리오 **IN** 가게가 스냅샷에 있음 / **OUT** 그 행을 인덱스에서 뺌(스냅샷에 없는 새 가게 → 동명 다른 가게에 붙음)
- 채점: **우리 32 카테고리 정확도**. 조건부 카테고리(음식점·편의점 등)는 카테고리에 따라 되묻는 질문이 달라지므로 판정 칸이 아니라 카테고리를 맞혀야 한다.
- 기준: 자동 확정한 것의 정확도 90% 이상.

## 결과

| 전국 · 전체 2만 건 | 조건 없이 | **확정 조건 t=0.9** |
|---|---|---|
| IN 자동 확정률 / 정확도 | 100% / 93.1% | **85.6% / 99.8%** |
| OUT 자동 확정률 / 정확도 | 44.0% / 79.0% | **32.2% / 91.1%** |

- 확정 조건을 걸면 IN·OUT 모두 90%를 넘는다. 실카드에서 둘이 어떤 비율로 섞여도 기준을 지킨다.
- t 는 0.9 와 0.95 사이 차이가 거의 없고, 0.8 로 내리면 OUT 이 90.5%로 경계에 붙는다.
- 잔여분(전국 1곳뿐 + 키워드룰 미적중)은 IN 이면 99.9%, OUT 이면 거의 못 찾는다(0.8%) → 되묻기로 간다.
- **시도로 좁혀서 비율을 재면 안 된다.** OUT·시도 조건에서 t=0.9 정확도가 87.8%로 떨어진다. 시도 안의 동명 가게가 1~2곳뿐이라 비율이 쉽게 100%가 되기 때문이다. 확정 비율은 전국 분포로 잰다.
- 약한 카테고리(IN 전국): 도서 82% · 수리비 84% · 광고 86% · 사무용품 87% · 여비교통 88% · 카페 89%.

## 채택하지 않은 조건

- **같은 이름 가게 ≥ 2곳일 때만 확정**: OUT 정확도는 97%로 오르지만 IN 확정률이 26%로 무너진다.
  전국 1곳뿐인 가게는 그 가게 자신인지 동명 다른 가게인지 구분할 수 없어 전부 버리게 된다.

## 한계

- **실카드 적중률(스냅샷에 있는 비율)은 이 데이터로 잴 수 없다.** 되묻기 물량은 이 값으로 정해진다.
- IN 은 카드 문자열과 상권 상호명이 같은 원본에서 나왔다. 실제로는 카드사 등록 상호(법인명)와 간판명이 다를 수 있다.
- 상권정보는 오프라인 점포만 담는다. 해외 SaaS·온라인 결제는 커버리지 0%라 별도 경로(도구 사전 + 미지 해외 결제는 구독서비스로 되묻기)가 필요하다.
- 매핑표는 초안이다. `★검토` 행, 특히 **입시·교과학원 → 교육(940909 통상)** 은 1인 IT 사업자에게 개인 지출이라 카테고리 체계 차원의 과대계상 위험이 있다.
