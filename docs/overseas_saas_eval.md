# 카테고리 분류: 해외 결제 — 도구 사전 매칭

측정일 2026-10-01. 재현: `tools/exp_overseas_saas/README.md`.
가맹점 데이터셋 매칭(`docs/merchant_matching_eval.md`, PR #61)은 상권정보(오프라인 점포)라 해외 SaaS 커버리지가 0%다.
그 빈칸을 SaaS 목록 사전으로 채운다. 구조는 같다 — **사전으로 확정, 못 찾으면 되묻기.**

## 방식

```
결제 문구 → 키워드룰(rules/keyword_rules.yaml) → 도구 사전(dict.csv)
   ├ 사전에 있음 → 해외SaaS·게임 자동 확정
   └ 없음 → 결제대행만 보이면 PG_미상, 아니면 미분류(분류 확인 → 사용자가 후보 중 선택, api.md 2.4)
```

- 은행 문구·결제대행 접두어(`PAYPAL *`, `PADDLE.NET*`, `GOOGLE *` 등)를 떼고 브랜드 부분만 본다.
- 도메인형(`GITHUB.COM`)은 강한 증거. 토큰형은 흔한 영단어면 브랜드 첫 토큰일 때만 인정한다.
- `GOOGLE`·`MICROSOFT`·`AMAZON` 같은 우산 브랜드는 사전에서 직접 확정하지 않는다(키워드룰이 맡음).

## 결과 (평가 94건, 해외SaaS 46건)

자동 확정 = 사용자 분류 없이 카테고리가 정해진 것(미분류·PG_미상 제외).

| | 자동 확정 | 확정 정확도 | 도구 재현율 |
|---|---|---|---|
| A 키워드룰만 (develop 현재) | 38 | 37/38 | 24/46 (52%) |
| **B 키워드룰 + 사전** | **54** | **53/54** | **40/46 (87%)** |
| C 사전만 | 46 | 46/46 | 35/46 (76%) |

- 사전을 붙이면 도구 재현율이 52% → 87%로 오르고, 사전이 낸 확정에는 오답이 없다.
- B 의 오답 1건은 키워드룰 쪽이다: `MICROSOFT *XBOX MSBILL.INFO`(게임)가 `MICROSOFT` 룰(p=800)에 걸려 해외SaaS. 기존 룰의 과대계상이라 별도로 고친다.

## 놓친 것 (B 기준 도구 6건 + 게임)
- 대행사 뒤 이름이 사전 형태와 다름: `GOOGLE *ZOOMdotUS`, `GOOGLE *Workspace_1871` → PG_미상
- 사전에 없는 소규모 도구: `PADDLE.NET* GETASTRA`, `PADDLE.NET* - CLASSMARKR` → PG_미상
- 잘린 이어붙임·청구 도메인만 있음: `DROPBOXINTE`, `MSFT *<...> MSBILL.INFO` → 미분류
- 게임사(Steam·Epic·Riot·Blizzard 등)는 사전에 없어 미분류로 간다.

## 모르는 해외 결제를 구독서비스가 아니라 미분류로 보내는 이유
1차 실험은 모르는 해외 결제를 구독서비스로 넘겨짚고 용도를 되물었다. 그러면 게임 8건이 구독서비스로 확정되고
'업무 관련 구독인가'라는 엉뚱한 질문을 받는다. 미분류로 두면 분류 확인에서 사용자가 카테고리를 고른 뒤
그 카테고리의 질문을 받는다. B 기준 미분류 22건(정답: 구독서비스 12 · 게임 8 · 해외SaaS 2)이 이 경로로 간다.

## 한계
- 평가셋이 94건으로 작다. 9/28 1차 실험 때 오답을 이미 봤으므로, **이 평가셋에 맞춰 규칙을 고치지 않았다.** 고친 뒤에는 새 샘플로 다시 잰다.
- 실카드 원본이 없어 해외 결제가 실제로 어떤 표기로 오는지 비율은 모른다.
