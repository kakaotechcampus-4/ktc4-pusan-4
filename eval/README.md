# 판정 평가셋

`eval/cases/E-*.yaml` 한 건 = 거래 하나와 그 거래가 받아야 할 판정. 하네스는
`backend/src/test/java/com/ktc4/pusan4/eval/EvalHarnessTest.java`.

**기대값은 규칙 카드가 아니라 조문에서 뽑는다.** 카드에서 뽑으면 자기가 자기를 채점한다(CONTEXT §16-11).
케이스마다 `근거`에 조문 요지를 먼저 쓰고 기대값을 거기서 도출한다. 기대값에 카드 ID를 쓰지 않는다.

## 실행

```bash
# CI 조건 (레포의 rules/ 그대로)
backend/gradlew -p backend test

# 다른 규칙 디렉터리로 측정 (예: 커밋 전 카드)
EVAL_RULES_DIR=<경로>/rules backend/gradlew -p backend test --tests com.ktc4.pusan4.eval.EvalHarnessTest
```

리포트: `backend/build/reports/eval/eval-report.md` (관문별 일치·미달·치명·보류 + 케이스별 문제).
`rules/cards/`가 없으면 빈 규칙셋으로 돈다 — 전부 확인필요라 치명이 나올 수 없다.

> Windows에서 `--tests "*Eval*"`처럼 와일드카드를 쓰면 Java 런처가 현재 디렉터리의 `eval/`로
> 펼쳐 테스트를 못 찾는다. 클래스 이름을 그대로 쓸 것.

## 형식

```yaml
id: E-001
관문: G1                         # G1~G6 / 엣지 (집계용)
제목: 업무 이동 중 주차위반 과태료
사업자컨텍스트: { 업종코드: "940909", 직원있음: false, 자택작업실_비율: 20 }   # 업종코드는 따옴표 필수
거래:
  일자: 2025-03-14
  가맹점: "부산광역시청 주정차위반과태료"
  금액: 50000
  merchant_category: 지자체_과태료   # fixture. rules/categories.yaml 안의 값만. 분류기는 평가 대상 아님
  비고: "..."                        # 사람용. 엔진 입력 아님
응답:                                # 선택. 되묻기 답변 fixture
  - { 범위: transaction, fact_type: 용도, 값: 업무미팅 }   # 범위: transaction | merchant
기대:
  판정: 불가                         # 가능 / 불가 / 확인필요
  걸린게이트: G1                     # 선택. G1 / G2 / null (키를 빼면 채점 안 함)
  근거조문_포함: [소득세법-33-1-2]
  근거조문_제외: [소득세법-33-1-12]  # 인용하면 근거 오적용
  is_inference: false                # 선택
  속성: { 가산세_대상: false }       # 선택. 적은 키만 비교, null = 없어야 함
  금액: 583333                       # 선택. 금액 산정 구현 전까지 채점 안 함
채점: { 치명: true, 보류: false }   # 보류는 선택. true면 채점 안 함
근거: "조문 요지"
```

## 채점

| 결과 | 조건 | CI |
|---|---|---|
| 치명 | 실제 `가능`인데 기대는 `가능`이 아님 (오탐) | 실패 |
| 치명 | 실제 `불가`인데 기대는 `가능` (미탐) | 실패 |
| 치명 | `근거조문_제외` 조문을 인용 | 실패 |
| 치명 | 실제 `가능`/`불가`인데 근거 0건 | 실패 |
| 치명 | `치명: true` 케이스에서 실제 판정이 확정(가능/불가)인데, 판정·걸린게이트·근거·속성 중 하나라도 기대와 어긋남 | 실패 |
| 미달 | 그 외 불일치 (예: 기대 불가인데 확인필요) | 통과, 리포트에 기록 |
| 보류 | `채점.보류: true` | 채점 안 함 |

확인필요는 판정을 넘긴 것이지 틀린 답을 준 게 아니라 치명이 아니다.

## 한계

- **라벨러 1명.** CONTEXT §11은 2명 독립 라벨링이다. 첫 배치 50건은 규칙 카드 작성자가 혼자 썼다 — 두 번째 라벨러가 필요하다.
  보류가 아닌 45건은 검수 전이라도 전부 머지 차단 기준이다. CI가 치명으로 막히면 코드가 아니라 기대값이 틀렸을 수 있으니 조문부터 확인한다.
- **속성 키는 조문이 아니라 엔진 계약이다** (`가산세_대상`, `자산`, `limit_bucket`). 속성 채점은 판정·근거 채점보다 증거력이 약하다.
- **금액·G0(입력 검증)은 채점하지 않는다.** 둘 다 `judge()`에 아직 없다.
- **보류 5건**은 조문 해석이 갈려 기대값을 확정하지 않았다. 사유는 각 케이스 `근거`에:
  E-007 본인 교육비 · E-028 카페 혼자 작업 · E-036 자택 겸 작업실(시행령 §61①1 후단) ·
  E-042 소프트웨어 무형자산 · **E-045 개인용 컴퓨터(시행령 §67⑦4 — 히어로 시나리오 전제와 충돌)**
