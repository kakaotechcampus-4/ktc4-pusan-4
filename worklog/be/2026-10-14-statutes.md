# GET /statutes/{id} 를 목에서 statute_version 조회로 바꾼다 (A0)

- 브랜치: feature/statutes (base: develop)
- 커밋: 380a146 (1개)
- 주요파일: StatuteService.java, StatuteVersionEntity.java, StatuteController.java, StatuteIntegrationTest.java

## 한 일

- `StatuteService.get(statuteVersionId)` 가 `statute_version` 을 id 로 찾아 도메인 `StatuteVersion` 으로 돌려준다. 없으면 404 `STATUTE_NOT_FOUND`.
- `StatuteVersionEntity` 에 응답에 필요한 컬럼(title, hierarchy, source_url, body)을 매핑했다. 마이그레이션은 없다.
- 컨트롤러의 `@MockResponse` 와 `JudgmentMockData.statute()` 를 지웠다. `ApiResponseContractTest` 는 `@MockitoBean StatuteService` 로 계약만 본다.

## 왜 이렇게 했나

- 스택(#126 → #127 → #128)에 쌓지 않고 develop 에서 땄다. `StatuteController`·`StatuteVersionRepository` 가 이미 develop 에 있어 run 쪽 코드가 필요 없다. 먼저 merge 될 수 있다(사용자 결정).
- 소유자 확인을 하지 않는다. `statute_version` 은 `law_sync.py` 가 쌓는 공용 원문이고 사용자 데이터가 아니다.
- 서비스·도메인·`Response.from` 구조는 B1b(`BusinessContextService`)를 따랐다.

## 확인한 것

- `StatuteIntegrationTest` 2개: 저장한 원문의 8개 필드가 그대로 나온다, 없는 id 는 404 `STATUTE_NOT_FOUND`.
  - 첫 테스트는 목 상태에서 먼저 실패(`statuteVersionId` 1418)하는 것을 봤다.
  - 404 테스트는 구현이 먼저 들어가 있어, 에러 코드를 일부러 바꿔 실패하는 것을 확인했다.
- `gradlew -p backend check` 통과(test 288, integrationTest 53).

## 남은 것 · 아는 문제

- #127 도 `ApiResponseContractTest` 의 같은 자리에 `@MockitoBean JudgmentRunService` 를 넣는다. 이 PR 이 먼저 merge 되면 develop 을 스택에 merge 할 때 충돌이 난다. 두 줄 다 남기면 된다.
