# 공휴일을 API 로 받지 못한 해가 표에 없으면 시드로 채운다

- 브랜치: feature/holiday-seed-fallback
- 커밋: 07a5a3f..07a5a3f (1개)
- 주요파일: HolidaySync.java, HolidayCalendar.java, HolidaySeed.java, holiday/seed.txt

## 한 일

- `holiday/seed.txt` 에 2025~2027 공휴일 65건을 넣었다. 특일정보 API 를 2026-10-20 에 실제로 호출한 응답이고(2025 19건, 2026 22건, 2027 24건), 같은 날 공휴일은 `HolidayApiClient` 와 같은 규칙으로 이름을 합쳤다.
- `HolidaySeed` 가 기동할 때 이 파일을 읽어 `holidays(year)` 로 연도별 목록을 준다.
- `HolidaySync.syncYear` 는 호출이 실패하거나 빈 응답이 오면 `fillFromSeed(year)` 를 부른다.
  - `HolidayCalendar.fillYearIfEmpty` 가 교체용 잠금을 건 뒤, 그 해 행이 하나도 없을 때만 시드를 넣는다.
  - 시드 저장이 실패해도 경고만 남긴다(기동을 막지 않는다).
- `docs/deployment.md` §7 에 시드 동작과 시드를 갱신해야 하는 시점을 적었다.

## 왜 이렇게 했나

- PR #107 멘토 리뷰에서 나온 "최초 배포 때 공휴일을 데이터로 미리 두고 주기적으로 sync" 를 사용자 요구 두 가지로 좁혔다.
  1. API 로 이미 받은 해에는 시드를 쓰지 않는다.
  2. 그 해를 API 로 한 번도 받지 못한 상태에서 실패했을 때만 시드를 쓴다.
- 그래서 마이그레이션으로 시드를 미리 넣지 않았다. 미리 넣으면 기존 DB 에서 API 가 이미 지운 날(취소된 임시공휴일 등)이 되살아날 수 있다.
- "그 해 행이 있는가" 로 판단한다. 시드로 채운 해도 행이 있으므로 다시 넣지 않는다. 다음에 API 가 성공하면 `replaceYear` 가 시드 행을 통째로 바꾼다. 출처 컬럼은 이 판단에 필요 없어서 만들지 않았다.
- 확인과 삽입을 한 트랜잭션에서 `lockForReplace` 아래 한다. 따로 하면 그 사이 다른 서버의 API 교체가 끝났을 때 시드가 덮을 수 있다.
- 빈 응답도 시드 대상으로 봤다. 발표 전 해는 시드에도 없어 아무 일도 안 일어나고, 올해가 비어 오는 건 고장이라 시드가 맞다.
- 키가 없을 때는 지금처럼 건너뛰고 시드도 넣지 않는다. 키가 없는 로컬·테스트에서 표가 비어 있다고 가정하는 테스트(`JudgmentExecutorIntegrationTest` 의 한글날 전환)가 있고, 운영은 키가 있다.
- 리소스 이름이 `.csv` 가 아니라 `.txt` 다. `.gitignore` 가 카드 내역 유출을 막으려고 `*.csv` 를 막고 있어서 그 규칙을 건드리지 않았다.

## 남은 것 · 아는 문제

- 시드는 2027 년까지다. 동기화 범위(올해 앞뒤 1년)가 2028 년에 닿기 전(2027 년 중)에 다음 해를 덧붙여야 한다. 자동으로 알려 주는 장치는 없다.
- 실제 앱을 빈 DB 와 잘못된 키로 띄워 기동 직후 시드가 들어가는 것까지는 돌려 보지 않았다. `syncYear` 경로는 통합 테스트로, 기동 시 호출 경로는 기존 코드 그대로다.

## 16:57 시드를 API 응답 원본 JSON 으로 바꿈

### 한 일

- `seed.txt` 를 지우고 `holiday/seed/{연도}.json` 에 같은 날(2026-10-20) 받은 특일정보 API 응답을 그대로 두었다. 2025 응답은 테스트 샘플 `rest-de-info-2025.json` 과 바이트까지 같다.
- `HolidayApiClient.fetch` 에서 응답 해석 부분을 `static parse(root, year)` 로 떼어 냈다. 동작은 그대로다.
- `HolidaySeed.holidays(year)` 는 그 해 파일이 있으면 `parse` 로 읽고, 없으면 빈 목록이다.
- `fillFromSeed` 가 시드 읽기도 try 안에서 한다.
- 테스트
  - `HolidaySeedTest`: 연도별 파일을 읽는다(19·22·24건), 파일 없는 해는 비어 있다. 시드와 API 해석 결과를 비교하던 테스트는 이제 같은 코드를 지나므로 뺐다.
  - `HolidaySyncTest`: 시드가 깨져 있어도 예외가 밖으로 나가지 않는다.

### 왜 이렇게 했나

- 리뷰(사용자): "날짜,이름" 형식은 이름에 쉼표가 들어가서("어린이날, 부처님오신날") 첫 쉼표에서만 자르는 규칙에 기대고 있었다. 게다가 `.gitignore` 때문에 확장자를 `.txt` 로 바꾸면서 CSV 의 이점도 없어진 자체 형식이었다.
- 원본을 두면 같은 날 이름 합치기, `isHoliday=Y` 고르기, 잘린 응답 거부까지 API 와 같은 규칙이 그대로 적용된다. 다음 해는 응답을 받아 저장하기만 하면 된다.
- 시드를 이제 쓸 때 읽는다. 파일이 깨져 있으면 `parse` 가 던지는데, 기동 직후 동기화에서 이 예외가 나가면 애플리케이션이 뜨지 못한다. 그래서 읽기도 저장과 같은 try 로 감쌌다.
