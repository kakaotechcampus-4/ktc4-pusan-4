# 비밀번호 규칙, 변경, 재설정과 버그 신고 API

## 한 일

#268 「BE」 항목 중 비밀번호 조건, 버그 신고, 비밀번호 재설정과 사용자 비밀번호 변경을 만들었다. 카카오·이메일 계정 연결은 하지 않았다.

- 비밀번호 규칙: 영문자, 숫자, 기호(영문자·숫자가 아닌 출력 가능한 ASCII)를 하나씩 넣은 8자 이상, 72바이트 이하. `Passwords.requireValid` 한곳에서 보고 이유를 담아 400 `VALIDATION_ERROR` 를 준다. 가입, 변경, 재설정이 쓰고 로그인은 보지 않는다.
- 비밀번호 변경 `PUT /users/me/password`: 현재 비밀번호 확인 → 규칙 → 모든 로그인 끊기 → 해시 변경, 204. 비밀번호 없는 계정은 409 `PASSWORD_NOT_SET`, 현재 비밀번호가 틀리면 400 `INVALID_CURRENT_PASSWORD`.
- 비밀번호 재설정 `POST /auth/password-reset`(202) → `/confirm`(토큰) → `/complete`(204). 가입하지 않은 이메일도 202 이고 메일은 안 보낸다. 재설정하면 모든 로그인을 끊는다.
- 인증 코드 저장소와 메일 발송기에 용도(`VerificationPurpose`: 가입, 재설정)를 넣었다. Redis 키 앞부분과 메일 제목·본문이 용도마다 다르다. 가입 키 이름은 예전 그대로다.
- 버그 신고 `POST /bug-reports`(202): 로그인 사용자만, 팀 메일로만 보낸다(저장 안 함). 받는 주소는 `app.bug-report.to`, 비면 보내는 계정. 사용자마다 한 시간 5건. 메일 계정이 없으면 503.

## 왜 이렇게 했나

- 정한 것(대화): 문자는 영문만, 기호는 ASCII, 공백·한글은 막지 않음, 대문자 필수 아님. 변경 뒤에는 지금 기기도 다시 로그인. 재설정은 항상 202. 버그 신고는 로그인 사용자만, 메일로만.
- 규칙을 Bean Validation 애너테이션으로 두지 않았다. `ApiExceptionHandler` 가 입력 검증 오류 문구를 「요청 값이 올바르지 않습니다」 하나로 바꿔 이유가 남지 않는다. 원래 72바이트 검사도 서비스에서 이유를 담아 던지고 있었다.
- 변경과 재설정 모두 로그인을 먼저 끊고 비밀번호를 바꾼다. 탈퇴와 같은 이유로, Redis 가 실패하면 비밀번호도 바뀌지 않아 옛 로그인이 남지 않는다.
- 재설정은 가입 인증과 같은 저장소(재발송 대기 60초, 하루 5개, 5번 틀리면 폐기)를 용도별 키로 쓴다. 용도를 나누지 않으면 키가 이메일 하나라 가입 토큰과 재설정 토큰이 같은 자리를 쓴다.
- 재설정 토큰은 `consumeVerified` 가 지운 요청만 이어 가서, 같은 토큰으로 동시에 와도 한 번만 바뀐다.
- 재설정의 202 는 가입 여부를 숨기려는 것인데, 가입한 이메일만 429(대기)·502 를 받을 수 있어 완전히 숨지는 않는다. 가입 인증의 409 가 이미 가입 여부를 알려 줘서 더 막지 않았다(api.md 에 적음).
- 버그 신고는 FE 가 지금 메일 링크로 받는다(`BugReport.tsx`). 받는 주소의 기본을 보내는 계정으로 둔 것은 FE 의 문의 주소(`utils/contact.ts`)와 같은 팀 계정이라고 보아서다. 다르면 `APP_BUG_REPORT_TO` 로 바꾼다.

## 03:18 비밀번호에 공백과 한글을 쓸 수 없게 한다

- 커밋: 83d6ec28 (1개)
- 주요파일: Passwords.java, PasswordsTest.java, docs/api.md

### 한 일

- 새 비밀번호는 출력 가능한 ASCII(`!`~`~`)만 받는다. 공백, 탭, 한글, 이모지 등은 400 `VALIDATION_ERROR` 「비밀번호에는 공백이나 한글을 쓸 수 없습니다」.
- ASCII 라 72바이트 한도가 72자가 되어 규칙 문구를 「8자 이상 72자 이하」로 바꿨다. 로그인은 그대로 바이트로만 본다.

### 왜 이렇게 했나

- 공백과 한글을 막기로 정했다(대화). 한글만 골라 막지 않고 ASCII 밖을 모두 막은 것은 기호의 범위가 이미 ASCII 라, 남는 문자가 그것뿐이어서다.
- 이전 규칙으로 공백이나 한글을 넣어 가입한 사용자는 로그인할 수 있고, 바꿀 때만 새 규칙을 따른다.

### 확인한 것

- 새 테스트를 먼저 써서 16건 중 12건 실패를 보고 고쳤다. `PasswordsTest` 16건, `AuthIntegrationTest` 35건, 단위 전체 통과. 통합 전체(`check`)는 이 커밋으로 다시 돌리지 않았다.
