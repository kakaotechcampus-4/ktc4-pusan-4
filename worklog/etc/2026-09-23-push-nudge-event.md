# push-nudge 훅이 안 돌던 문제 수정

- 브랜치: feature/make-worklog
- 커밋: 34941ab 이후 1개
- 주요파일: `.claude/settings.json`

## 한 일

- 훅 이벤트를 `PostToolUse` 에서 `PostToolUseFailure` 로 바꿨다.
- `.claude/hooks/push-nudge.sh` 는 고치지 않았다. stdin JSON 을 통째로 grep 해서
  출력이 `error` 필드에 담기든 `tool_response` 에 담기든 똑같이 잡힌다.

## 왜 이렇게 했나

`PostToolUse` 는 도구 호출이 **성공했을 때만** 돈다. 게이트에 막힌 push 는 exit 1 이라
Bash 호출이 실패로 처리되고, 그래서 훅이 불리지 않았다. 게이트를 통과한 push 는
안내 문구가 없어서 아무 일도 안 한다 — 결국 필요한 순간에만 안 도는 훅이었다.
PR #46 리뷰에서 지적받았다.

처음 "발동을 확인했다" 고 본 것은 성공한 Bash 호출이었다. 실패 경로로 시험하지 않아
반례를 못 봤다. 이번엔 실패하는 호출로 검증했다.

## 남은 것 · 아는 문제

- `exit 2` 는 차단이 아니라 stderr 가 시스템 메시지로 전달되는 것이다.
  이 훅은 지시를 전달하는 용도라 그대로 둔다.
- 터미널에서 직접 push 하는 경로는 여전히 수동이다. Claude 밖의 일이라 알 방법이 없다.

## 15:07 같은 날이면 이어쓰기로 규칙 변경

PR #46 두 번째 리뷰 반영. push 마다 새 문서를 만들면 하루에 여러 번 push 할 때
기록이 쪼개지고, CLAUDE.md 의 "최신 2개 읽기" 가 같은 날 조각 둘만 읽게 된다는 지적이었다.

훅은 고치지 않았다. 게이트 판정이 "범위에 `worklog/<도메인>/` 변경이 있는가" 라서
기존 문서를 고친 커밋도 원래 통과한다. 막고 있던 것은 훅이 아니라 문구였다.

- `.claude/skills/worklog/SKILL.md` — 같은 날 같은 도메인 문서가 있으면 새로 만들지 않고
  `## <HH:MM> <한 줄 요약>` 을 끝에 붙인다. 여러 개면 가장 최근 것.
- `worklog/README.md`, `CLAUDE.md` 6절 — append-only 를
  "이미 쓴 줄은 고치지 않고 끝에만 덧붙인다" 로 정의했다.

리뷰어가 제안한 "오늘 날짜 문서가 있으면 통과" 는 택하지 않았다. 아침에 하나 쓰면
하루 종일 무제한 push 가 되어 강제력이 사라진다. 이어쓰기는 매 push 마다 기록을
요구하면서 파편화만 없앤다.
