## 한 일

- 실서버 모드 로그인 화면이 열리면 이메일 칸에 `demo-<uuid>@demo.test` 를 채워 둔다. 사용자는 비밀번호만 넣으면 된다.
- 만든 이메일은 localStorage `demo-email` 에 두고, 같은 브라우저로 다시 오면 그 값을 쓴다. 로그아웃 뒤 다시 들어와도 같은 계정이다.
- localStorage 를 못 쓰는 브라우저는 그 화면에서만 쓰는 이메일을 새로 만든다. 다시 오면 다른 계정이 된다.
- 목업 모드는 예전처럼 빈 칸이다. 백엔드는 그대로다(처음 보는 이메일은 `findOrCreateByEmail` 이 가입시킨다).
- 안내 문구를 "이 브라우저용으로 만들어 두었으니 비밀번호만 입력" 으로 바꿨다.
- 확인: frontend typecheck·vitest 158 통과, `VITE_API=http` 빌드 성공. 빌드 결과를 로컬 preview 로 열어 이메일이 채워지고 새로고침 뒤에도 같은 값인 것을 봤다.

## 왜 이렇게 했나

- 10/22 에 이메일 자유 가입을 붙였지만, 발표장에서는 여러 사람이 `test@test.com` 같은 같은 이메일을 넣을 가능성이 높다. 그러면 한 계정으로 들어가 409(`DUPLICATE_FILE`)와 사전·답변 섞임이 다시 생긴다.
- 버튼 한 번으로 바로 로그인시키는 방법도 있었지만, 입력란을 미리 채우는 쪽을 골랐다. 이메일을 직접 바꿀 수는 있어 일부러 같은 값을 넣으면 여전히 겹친다.
- `crypto.randomUUID()` 는 보안 컨텍스트에서만 동작한다. 데모 주소는 Caddy 가 HTTPS 로 연다.

## 남은 것 · 아는 문제

- 백엔드까지 붙인 실제 로그인은 로컬에서 하지 않았다. 배포 뒤 데모 주소에서 확인한다.

## 12:21 액세스 토큰 유효 시간을 15분에서 1시간으로 늘린다

- 커밋: f769778
- 발표 슬라이드(github.io)에 데모 화면을 iframe 으로 넣으면 다른 사이트 안이라 refresh 쿠키(`SameSite=Strict`)가 저장되지도 보내지지도 않는다. 로그인은 되지만 액세스 토큰이 끝나면 연장하지 못하고 로그인 화면으로 돌아간다.
- `application.yml` 의 `access-token-ttl` 을 1h 로 바꿨다. 이 값은 환경변수로 덮어쓸 수 없고 compose 도 넘기지 않아서, VM 설정이 아니라 이 브랜치에서 바꿨다. api.md(15분)는 실제 스펙이라 그대로 둔다.
- 쿠키를 `SameSite=None` 으로 푸는 쪽은 택하지 않았다. 서드파티 쿠키를 막는 브라우저에서는 어차피 안 붙는다. 1시간이 지나도 이메일이 localStorage 에 있어 비밀번호만 넣으면 같은 계정이다.
- 확인: auth 단위 18·`AuthIntegrationTest` 12 통과.
