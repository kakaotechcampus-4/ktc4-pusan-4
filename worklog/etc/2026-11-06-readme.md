# README 를 서비스 소개 페이지로 다시 씀

- 브랜치: feature/readme
- 주요파일: README.md, docs/img/readme/

## 한 일

- 레포 첫 화면 README 를 서비스 소개 형식으로 바꿨다. 배너, 핵심 가치, 주요 기능 5개, 아키텍처, 기술 스택, 디렉터리 구조, Git 규칙, 코드 컨벤션, 팀원 순서다.
- 배너는 Really 캐릭터 이미지와 PreeT 흰색 로고(`frontend/src/assets/brand/logo/preet-logo-white.svg`)로 만들었다.
- 아키텍처 그림은 `deploy/compose.yaml`, `deploy/Caddyfile`, `deploy/rule-candidates.sh` 를 보고 archify 로 그렸다. 원본은 `docs/img/readme/architecture.json` 이다.
- 기능 GIF 4개는 실서버에서 업로드 화면의 샘플 파일(KB국민)로 찍었다. 헤더의 계정 이메일은 가렸다.

## 왜 이렇게 했나

이전 README 는 백엔드 실행 안내뿐이라 레포에 처음 온 사람이 무엇을 만드는 팀인지 알 수 없었다. 백엔드 실행·배포 안내 링크는 `로컬 실행` 절에 그대로 남겼다.

## 남은 것 · 아는 문제

- 아키텍처 그림과 GIF 는 자동으로 갱신되지 않는다. 서비스 구성이나 화면이 바뀌면 `architecture.json` 을 고쳐 다시 그리고 GIF 를 다시 찍는다.
- 샘플 데이터에 접대비·100만원 초과 자산이 없어 summary.gif 에는 한도·감가상각 장면이 없다.
- GIF 는 캡처를 이어 붙인 것이라 장면이 끊겨 보인다.

## 아키텍처 그림 해상도 올림

- 1배율 캡처라 글자가 흐려서 2배율(3630×1630)로 다시 캡처했다.
- 라이트·다크 두 장을 두고 `<picture>` 로 GitHub 테마에 맞춰 보여 준다.

## 아키텍처 그림을 흐르는 GIF 로 바꿈

- GitHub README 는 JavaScript 를 막아 archify 뷰어의 마우스 반응 효과를 쓸 수 없다. 대신 연결선을 따라 빛 점이 흐르는 GIF 로 바꿨다.
- 연결선 좌표는 archify HTML 의 `path[data-edge-id]` 에서 뽑고, 2배율 정적 그림 위에 점을 그려 30프레임으로 만들었다. 라이트·다크 두 장이다.
- 그림을 고칠 때는 `architecture.json` 으로 HTML 을 다시 만들고 같은 방법으로 GIF 를 다시 만든다.

## 배너의 돼지 경계선 없앰

- 돼지를 사각형으로 잘라 가장자리만 흐리게 했더니, 말풍선 쪽에 원본 배경 파랑이 남고 배너 배경과 색이 달라 선이 보였다.
- 원본 배경 파랑을 투명하게 빼고(바깥과 이어진 영역만, 눈·하트 같은 안쪽은 남김) 돼지만 얹었다. 바닥 그림자는 CSS 로 따로 그렸다.

## 배너 돼지 선명도 개선

- 원인: 브랜드 시트에서 잘라낸 돼지 원본이 610×545px 라 배너(2배율)에서 약 1.6배 늘어나 흐려 보였다
- 조치: 원본을 2배(1220×1090)로 Lanczos 확대 후 언샤프 마스크를 걸고 배경을 다시 오려 배너를 재렌더링. 이제 배너에서는 축소되어 그려진다
- 한계: 원본 이상의 디테일은 생기지 않는다. 더 선명하게 하려면 디자인 원본(고해상도 PNG)이 필요하다

## 실행·배포 섹션 빈 칸 추가

- 「로컬 실행」(링크 2개)을 「실행 · 배포」로 바꾸고 빠른 시작·환경 변수·파트별 실행(BE/FE/AI)·배포 칸만 만들었다
- 내용은 임의로 채우지 않고 각 파트 담당자에게 PR 댓글로 작성을 요청했다 (AI 서버 실행 방법은 저장소에 문서가 없음)
