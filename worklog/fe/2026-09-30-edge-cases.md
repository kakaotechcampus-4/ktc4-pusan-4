# 화면 간 상호작용 점검과 버그 수정

- 브랜치: `feature/transactions`
- 주요파일: `frontend/src/pages/Confirm.tsx`, `frontend/src/pages/Run.tsx`, `frontend/src/pages/ClassificationPreview.tsx`, `frontend/src/api/mock/index.ts`

## 한 일

화면별로만 확인하다가 "전부 잘 되는가" 를 묻길래 전 라우트를 데스크톱·모바일에서 이어서 돌려 봤다. 모든 화면이 에러 없이 뜨고 가로 스크롤도 없었지만, **배치를 지운 뒤** 화면들이 어긋나는 것을 찾았다.

- **판정 시작 버튼이 조용히 아무 일도 안 했다.** `batchId` 나 `contextRef` 가 없으면 `start()` 가 그냥 return 했는데 버튼은 활성 상태였다. 내가 `DESIGN.md` 에 적은 "눌리는데 아무 일 없는 버튼은 만들지 않는다" 를 내가 어겼다. 이제 비활성으로 두고 **막힌 이유**("올린 카드내역이 없습니다" / "사업자 문진을 먼저 마쳐 주세요")를 보여준다.
- **진행률이 영원히 0/0으로 돌았다.** 지워진 Run 을 조회하면 404 인데 실패를 삼키고 있었다. 이제 오류를 표시하고 업로드·이력으로 가는 길을 준다.
- **분류 확인이 「모든 거래를 분류했습니다」로 보였다.** 올린 배치가 없는 것과 다 분류한 것은 다르다. 배치가 없으면 빈 상태로 바꿨다.
- **목업이 배치 삭제를 계약대로 하지 않았다.** 배치만 지우고 거래·판정·리뷰·Run·질문이 남아서, 지운 뒤에도 `/transactions` 에 목록이 뜨고 `/results` 가 292건을 보여줬다. api.md 3.3 대로 파생 데이터까지 지운다.

## 왜 이렇게 했나

- **목업을 계약에 맞춘 이유**: 목업이 서버보다 관대하면 그 차이만큼 화면이 잘못 만들어진다. 삭제 후 목록이 남아 있는 걸 화면이 정상으로 보고 지나쳤다.
- **버튼을 숨기지 않고 비활성 + 이유로 둔 이유**: 버튼이 사라지면 사용자는 "여기서 판정을 시작할 수 있다" 는 것 자체를 모른다. 왜 못 하는지 알려주는 편이 다음 행동으로 이어진다.

## 남은 것 · 아는 문제

- `/upload` 는 아직 옛 목업(샘플 파일 고르기 + 가짜 파싱)이다. 브라우저 파서 TS 버전이 정해지지 않아 손대지 않았다.
- `/account` 는 라우트만 있는 빈 화면이다.
- 목업 집계는 292건 중 24건 샘플 위에서 도는 근사치다. 판정이 하나도 없으면 0 으로 떨어지게만 맞췄다.
