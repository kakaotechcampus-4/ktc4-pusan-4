# 판정 진행률의 부분 실패 처리

- 브랜치: `feature/transactions`
- 주요파일: `frontend/src/pages/Run.tsx`, `frontend/src/api/mock/index.ts`, `frontend/src/types/domain.ts`

## 한 일

- Run 상태를 `COMPLETED` 하나로만 보던 것을 `PARTIAL_FAILED` · `FAILED` 까지 구분한다. 제목이 「판정을 마쳤습니다」 / 「일부를 판정하지 못했습니다」 / 「판정하지 못했습니다」로 갈린다.
- `failedCount > 0` 이면 `GET /judgment-runs/{id}/failures` 를 불러 실패 목록을 보여준다. 실패 응답은 `transactionId` 만 주므로 그 배치의 거래를 한 번 더 받아 가맹점 이름·금액을 붙인다.
- 「다시 판정하기」는 같은 `batchId` · `contextId` 로 **새 Run 을 만든다**(api.md 3.6 재실행). 실패분만 재시도하는 엔드포인트는 계약에 없다.
- `JudgmentRunCreated` 에 계약대로 `batchId` · `contextId` · `contextVersion` 을 넣었다. 재시도에 필요한 값이 응답에 이미 있다.
- 지어낸 호출 로그(「가맹점 사전 조회 292건」, 「국가법령정보 API 호출 6건 · 실패 0건」)를 지우고 실제 Run 값(문진 버전·대상 건수·시작 시각·실패 건수)으로 바꿨다.
- 실패가 있으면 게이트를 전부 통과한 것처럼 초록으로 칠하지 않고, 아래에 「일부 거래가 이 경로를 끝까지 통과하지 못했습니다」를 붙인다.

## 왜 이렇게 했나

- **지어낸 로그를 지운 이유**: 2건이 실패한 화면에서 「실패 0건」이라고 적혀 있었다. 어느 API 로도 뒷받침되지 않는 값이라, 실패가 생기는 순간 바로 거짓말이 된다. 화면에 있는 값은 전부 응답에서 온 것이어야 한다.
- **실패와 「확인 필요」를 구분해서 썼다**: 계약이 `NEEDS_REVIEW` 를 성공으로 센다(3.6). 사용자에게도 "판정이 안 된 것" 과 "판정은 됐는데 물어볼 게 있는 것" 은 다른 일이라 문구에서 갈랐다.
- **재시도가 전체 재실행이라는 것을 숨기지 않았다**: 새 Run 은 실패분만이 아니라 대상 전체를 다시 판정하고 새 revision 을 만든다. FR-43 은 「실패분만 재시도」라고 돼 있는데 계약에는 그런 엔드포인트가 없다. 지금은 전체 재실행으로 두고, 필요하면 BE 와 상의한다.
- **목업에 실패 주입 스위치를 넣었다**: 화면 코드가 알 필요 없도록 `mockControls.failNextRun(n)` 로 뺐다. 콘솔에서 `(await import('/src/api/index.ts')).mockControls.failNextRun(2)` 를 부르고 판정을 실행하면 부분 실패 화면을 볼 수 있다. http 구현으로 바꾸면 같이 사라진다.

## 남은 것 · 아는 문제

- 게이트 목록(G0~G6)과 그 진행 표시는 여전히 화면이 만든 연출이다. 어느 거래가 어느 게이트에서 막혔는지는 실패 응답(`errorCode` 만 준다)으로 알 수 없다.
- 실패 목록은 5건까지 보여주고 나머지는 「외 N건」이다. 전체를 보는 화면은 아직 없다.
- FR-43 의 「실패분만 재시도」는 계약에 없어 전체 재실행으로 대신한다.
