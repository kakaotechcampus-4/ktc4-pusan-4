# 내 정보 화면

스텁(15줄)으로만 있던 `/account` 를 만들었다. 계약 3.1 의 두 엔드포인트를 쓴다.

## 한 일

- 가입 이메일·가입일을 `GET /users/me` 로 읽어 보여준다
- 탈퇴(`DELETE /users/me`). 되돌릴 수 없으므로 `Modal` 로 한 번 더 묻고, 지우려는
  계정이 맞는지 이메일·가입일을 대화상자 안에 다시 보여준다. 끝나면 로그아웃하고
  랜딩으로 보낸다
- 조회 실패를 「없음」으로 보여주지 않는다. 「가입 정보를 불러오지 못했습니다」 +
  다시 시도
- `AppShell` 헤더의 이메일을 `/account` 링크로 바꿨다

## 왜 이렇게 했나

**또 라우트만 있고 링크가 없었다.** `/account` 를 참조하는 곳이 `App.tsx` 의 라우트
정의뿐이라 주소를 직접 쳐야 들어갈 수 있었다. `/transactions`·`/uploads` 와 같은
문제다. 헤더의 이메일이 이미 거기 있어서 그걸 링크로 바꿨다.

**탈퇴 안내에 추측을 쓰지 않았다.** 처음에는 "올린 카드내역과 판정 결과도 함께
사라집니다" 라고 쓰려 했는데, 근거가 없었다. `api.md` 는 `DELETE /users/me` 가 204 를
준다고만 하고 데이터 처리는 적지 않는다. 스키마를 보니 `transaction`·`judgment` 등의
`user_id` 가 `REFERENCES app_user(id)` 인데 **`ON DELETE CASCADE` 가 없다**
(`V1__create_judgment_core.sql`). 그래서 함께 지워진다고 말할 수 없고, 오히려 실제
DB 에서는 FK 때문에 삭제가 막힐 수도 있다. 확인된 것만 적고(계정이 삭제되고 다시
로그인할 수 없다), 카드내역을 먼저 지우고 싶으면 업로드 이력으로 가라고 안내한다.

## 확인

링크를 눌러 들어가고(`pushState` 로 건너뛰지 않음), 가입 이메일·가입일이 보이고,
탈퇴 모달이 Esc 로 닫히고, 탈퇴하면 랜딩으로 가고 그 뒤 `/account` 직접 진입은
로그인으로 막힌다. 기존 스위트 12개 회귀 없음. `build`·`lint`·`typecheck` 0.

## 남은 것 · 아는 문제

- 탈퇴 시 데이터가 어떻게 되는지 계약에 없다. 백엔드에 물어봐야 한다
- 목업 `users.remove` 는 아무것도 지우지 않는다. 화면이 바로 로그아웃하므로 흐름은
  같지만, 목업에서 다시 로그인하면 계정이 그대로 있다
