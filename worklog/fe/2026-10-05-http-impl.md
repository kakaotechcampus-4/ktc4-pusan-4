# 실제 서버 구현체를 붙이고 처음으로 실서버에서 돌려봤다

그동안 화면 검증은 전부 인메모리 목업 위에서만 했다. 배포 서버
(`https://ktc4-pusan-4.duckdns.org`)를 직접 때려 보니 필요한 엔드포인트가 전부
응답하고 있어서, 더 기다리지 않고 붙였다.

## 한 일

- `src/api/http.ts` — 계약 29개 메서드를 `fetch` 로 구현. 1.3 에러 봉투
  (`{code, message, traceId}`)를 `ApiRequestError` 로 그대로 올리고, 네트워크 실패는
  상태 0 `NETWORK_ERROR` 로 구분한다(화면이 "데이터 없음"으로 읽지 않도록)
- `POST /upload-batches` 에 `Idempotency-Key` 를 붙인다(1.6)
- `GET /users/me/contexts/current` 의 404 는 오류가 아니라 "문진 전"이므로 `null` 로 바꾼다(3.2)
- `src/api/index.ts` — `VITE_API=http` 면 실제 서버, 아니면 목업. `seedSession` 도 따라 바뀐다
- `vite.config.ts` — 개발 중에도 `/api/v1/*` 를 프록시한다. 배포에서 Caddy 가 하는 일과
  같은 경로를 쓰므로 화면 코드가 환경에 따라 달라지지 않는다
- `src/vite-env.d.ts` 신설(`import.meta.env` 타입)
- `mockControls` 를 `api/index.ts` 에서 다시 내보내지 않는다 — 내보내면 실제 서버
  빌드에서도 목업 모듈이 번들에 남는다

## 실서버에서 드러난 것

**업로드 이력에서 배치를 고를 수 없었다.** `setBatchId` 를 부르는 곳이 `/upload`
(새로 올릴 때)뿐이었다. 목업은 `mockSeedSession` 이 `batchId` 를 미리 넣어 줘서
안 보였는데, 실제 서버에서는 `seedSession` 이 null 이라 이미 올린 배치가 서버에
있어도 그 데이터를 볼 방법이 없었다. `/uploads` 는 선택된 행을 강조까지
하면서(`selectedKey`) 바꿀 수단이 없었다.

`이 파일 보기` 버튼을 넣었다. 행 클릭이 아니라 버튼인 이유는 행 안에 삭제 버튼이
이미 있어서다(DESIGN.md Table 규칙). 지금 보고 있는 배치는 `보는 중` 배지로 바뀐다.

실서버에서 확인했다 — 버튼을 누르면 `/transactions`·`/preview` 가 그 배치 데이터를
보여준다.

## 확인한 것

실서버(`VITE_API=http`)에서 11개 경로 전부 렌더, API 실패 0, 콘솔 에러 0.
목업 모드에서 기존 스위트 14개 전부 통과.

`build`·`lint`·`typecheck` 종료코드 0.

## 남은 것 · 아는 문제

- **서버가 아직 고정 목 응답이라 404 가 나지 않는다.** 없는 id 를 넣어도 200 에
  고정 데이터가 오고, 요청한 id 를 echo 하지도 않는다. 그래서 FE 의 404 경로
  ("업로드를 찾을 수 없습니다", "이 판정 실행을 찾을 수 없습니다")는 아직 한 번도
  돌지 않았다. 서비스 교체 뒤에 다시 봐야 한다
- `GET /judgments/summary?year=2026` 단독인데 `scope.type` 이 `BATCH` 로 온다. 명세는 `YEAR`
- `/results`·`/summary` 는 `runId` 기준이라 실서버에서 0건이다. 치오님 #90 이 `batchId`
  기준으로 바꾸는 중이라 그게 들어오면 풀린다
- 실제 서버 빌드에도 목업 데이터가 남는다(469KB → 451KB). `store` 초기화가 모듈
  최상위에서 돌아 롤업이 못 지운다. 동작에는 영향 없다
- `transactions.include/exclude` 응답이 계약대로 3필드인 것을 실서버에서 확인했다.
  FE 타입은 아직 `Transaction` 전체라 넓다. 지금은 응답을 쓰지 않아 안 깨진다

## 덧붙임 — 문진을 저장만 하고 다시 읽지 않았다

실서버에 붙이고 나서야 드러난 것들이다. 셋 다 목업이 가려 주고 있었다.

### `/confirm` 이 사용자 것이 아닌 문진을 보여줬다

`setContextRef` 를 부르는 곳이 문진 화면(새로 작성)뿐이라, 서버에 이미 문진이 있어도
세션은 비어 있었다. 그런데 화면은 `context ?? DEFAULT_CONTEXT` 로 **지어낸 값을
대신 보여주고** 있었다. "이 입력으로 판정합니다" 아래에 사용자 것이 아닌 숫자가 있었다.

| | 서버 실제값 | 화면이 보여주던 값 |
|---|---|---|
| 버전 | 1 | 4 (문자열로 박혀 있었다) |
| 직전연도 수입 | 82,000,000원 | 83,000,000원 |
| 개업일 | 2024-03-15 | 2024-03-01 |

- `SessionProvider` 가 로그인 뒤 `contexts.current()` 를 읽는다(3.2). 문진 전이면
  404 이고 http 구현이 null 로 바꿔 준다
- `DEFAULT_CONTEXT` 폴백 제거. 없으면 「아직 문진을 마치지 않았습니다」로 둔다
- 버전은 `contextRef.version` 을 쓴다

### `/confirm` 의 카드내역 칸이 비어 있었다

세션의 `ParsedBatch`(업로드 화면에서만 채워진다)를 보고 있었다. 업로드 이력에서
배치를 고르고 들어오면 `batchId` 는 있는데 그 객체가 없어 「아직 올린 카드내역이
없습니다」가 떴다. `api.uploads.get(batchId)` 로 읽도록 바꿨다. 보여주는 필드도
계약(`cardIssuer`·`sourceType`·`transactionCount`)에 맞췄다.

### 확인

실서버에서 흐름이 끝까지 돈다 — 업로드 이력에서 배치 고르기 → 확인 화면(서버 문진
버전 1, 82,000,000원) → 판정 시작 → `202 POST /judgment-runs` → 폴링 → 집계 →
「판정을 마쳤습니다 23 / 23건」. 콘솔·페이지 에러 0.
