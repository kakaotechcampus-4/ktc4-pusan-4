## 왜 이렇게 했나

- 도구 코드의 모양을 따른 것: 중계·진행 상황·지난번 답·세무대리인 질문 API 는 백엔드 일정에 없다. 실제 모양이 있는 곳이 비서 도구뿐이고, 그래야 FE 목과 비서가 같은 모양을 기대한다. 모양이 정해지면 `http.ts` 만 맞춘다
- 레이아웃 라우트에 올린 것: 화면마다 `AppShell` 이 따로 그려져 그 안에 두면 화면을 옮길 때마다 패널이 다시 만들어진다. 상태만 밖에 두면 열림·스크롤이 끊긴다
- `invalidateAll`: 패널은 화면 밖에 있어 화면의 `reload` 를 모른다. `useApi` 는 다시 읽는 동안에도 이전 data 를 들고 있어 화면이 비지 않는다
- 패널을 Modal 로 하지 않은 것: Modal 은 되돌릴 수 없는 동작 앞에서만 쓴다(DESIGN.md). 패널은 열어 둔 채로 화면을 쓴다
- 소명 대기에 지난번 답을 쓰지 않는 것: 건마다 사정이 달라 사용자가 직접 밝힌 사정만 근거가 된다(명세 3.1, 도구의 `NEEDS_USER_STATEMENT`)
- 데이터 경계 문장: 도구가 모델에 넘기는 필드(거래 승인일·가맹점명·카테고리·금액, 판정, 질문, 근거 조문, 진행 요약)에서 뽑았다. 수입·이름·이메일은 도구가 고르지 않는다

  - /results 에서 넷플릭스 행을 고르고 「가능으로 바꿔 줘」 → 판정 수정 카드 → [적용] 하자 패널이 「가능 · 사용자 수정」으로 바뀐다. 「확인 필요로」는 [적용] 없이 까닭만 뜬다
  - /questions 에서 「스타벅스는 업무미팅이었어」 → 답 카드 → [적용] 하자 그 카드가 목록에서 빠진다
  - 지난번 답: SK텔레콤·자택 관리비 카드에 「2025년 12월 업로드(국민)에서 …로 답했습니다」와 [이 답으로], Adobe·카페는 이력만, 소명 대기는 없음. 확인 목록 「2개 적용」 → 「지난번 답으로 질문 2개에 답했습니다」
  - 429 는 「5초 뒤에 다시 물어봐 주세요.」, 보낸 말이 입력칸으로 돌아온다. 422 문구도 따로 뜬다
  - 세무대리인 질문 카드를 적용하면 요약 문장 끝에 「따로 여쭐 것: 1) …」
  - 판정을 실행하면 「지난번 답으로 채울 수 있는 질문이 2개 있습니다」가 뜨고, [질문 보기]로 가면 닫힌다. 같은 실행 화면으로 돌아가도 다시 뜨지 않는다
  - 화면 아홉 곳을 옮겨 다녀도 대화가 남는다. 로그아웃하면 패널이 사라지고, 다시 로그인하면 빈 대화다
  - 375px 은 화면 전체(375×700), 640px 은 오른쪽 아래 400px 카드. 가로로 넘치지 않고, 맨 아래로 내려도 버튼이 페이지 넘김을 가리지 않는다
  - 개발 서버를 새로 띄운 뒤 콘솔 오류 없음. 띄운 채로 파일을 고치는 동안에는 Fast Refresh 가 모듈을 섞어 `useSession must be used within SessionProvider` 가 났는데, 새로 띄우면 나지 않는다

## 남은 것 · 아는 문제

- 중계·진행 상황·지난번 답·세무대리인 질문 API 와 질문 응답 `source`·질문 `code` 는 백엔드가 정한다. 그때 `http.ts` 를 맞춘다. FE 는 `code` 를 쓰지 않아(짝은 groupKey·factType) 넣지 않았다
- 데이터 경계 목록은 AI 쪽이 확정한다. `ai/assistant/kb.yaml` 의 데이터 경계(승인번호를 브라우저에만 둔다고 적음)와 승인내역 받는 길(홈택스)이 업로드 화면과 다르다
- 비서 도구는 판정 수정에 「확인 필요」를 제안할 수 있다. #62 에서 막기로 해서 FE 는 적용하지 않는다
- 이 브랜치와 `feature/auth-admin` 은 둘 다 `feature/fe-api-sync` 위에 있다. 같은 worklog 에 이어 쓰면 머지할 때 부딪혀서 따로 문서를 두었다
