# 업종코드를 KSIC 62010 에서 국세청 업종코드 940909 로 바꿨다

- 브랜치: feature/industry-940909 (feature/auth-admin 위)
- 커밋: 335ab9d..335ab9d (1개)
- 주요파일: frontend/src/pages/Interview.tsx, frontend/src/contexts/SessionContext.tsx, frontend/src/api/mock/data.ts, docs/api.md

## 한 일

- 문진 업종 선택지를 `940909` 「프리랜서 · 인적용역」, 힌트 「940909 기타자영업 (컴퓨터 프로그래머 등)」으로 바꿨다. 안내 문구도 같이 바꿨다
- `DEFAULT_CONTEXT`·목업 시드 문진·목업 테스트의 `industryCode` 를 `940909` 로
- 판정 화면 G2 문구, 히어로 트레이스, 스타일가이드 예시를 940909 로. 스타일가이드 Select 의 두 번째 예시는 940926(소프트웨어 프리랜서)
- 목업 규칙 후보 4건의 `industryCode` 와 초안 YAML `industry` 를 940909 로. 클라우드 판정 설명 문장을 인적용역에 맞게 고쳤다
- `ContextResponse` 스웨거 예시, `docs/api.md` 3.2 예시, `ApiResponseContractTest` 의 문진 값을 940909 로

## 왜 이렇게 했나

- 규칙 카드 20장이 모두 `industry: ["940909"]` 이고 페르소나도 940909 다(CONTEXT.md). 문진이 62010 을 보내면 G2 에서 모든 거래가 `RULE_NOT_FOUND` 로 「확인 필요」가 된다. 업로드→결과 통합 리허설에서 드러났다
- 62010 은 한국표준산업분류(KSIC) 코드라 국세청 업종코드와 체계가 다르다. 940909 는 국세청 세세분류 「기타자영업」(중분류 94 인적용역)이고, 적용범위에 「컴퓨터 프로그래머(소프트웨어 프리랜서 제외)」가 있다(upjong.co.kr/business-code/upjong-940909)
- 940926(소프트웨어 프리랜서)은 자격 요건이 붙고 카드가 다루지 않아 선택지에 넣지 않았다

## 확인한 것

- `npx tsc --noEmit` 통과, `npm run lint` 오류 0(기존 경고 10), `npm run build` 통과, `vitest` 127개 통과(`parity.test.ts` 는 원래대로 건너뜀)
- `ApiResponseContractTest` 통과
- 리허설 백엔드(#133·#130·#140 합친 로컬 브랜치)에 이 브랜치 기본값(940909)으로 문진을 만들고 같은 배치를 판정했다. 8건 모두 카드가 매칭됐다(가능 1, 불가 4, 확인 필요 3, 실패 0). 62010 으로는 8건 모두 `RULE_NOT_FOUND` 였다

## 남은 것 · 아는 문제

- 화면으로 끝까지 눌러 보지는 못했다. 이 브랜치의 실서버 로그인이 `/auth/login` 을 부르는데 아직 백엔드에 없다. 위 확인은 API 로 했다
- 리허설 판정은 로컬 DB 에 임시로 넣은 시행령 과거판에 기대고 있다. 실제 조문 이력 적재는 별도 작업이다
- 「준비 중」 업종 선택지(디자이너 73203 등)는 KSIC 값 그대로다. 선택할 수 없어 서버로 가지 않는다
- 랜딩·마케팅 문구의 「1인 IT 개발 사업자」는 그대로 뒀다. 940909 프로파일이 「IT 개발 + 강의」라 어긋나지 않는다
