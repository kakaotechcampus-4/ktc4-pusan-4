# Really 버튼을 원형 FAB 으로 바꾼다

- 브랜치: feat/brand-a11y-really
- 커밋: 44fd2cc (1개)
- 주요파일: Assistant.tsx, index.css

## 한 일

- 로그인 전·후 Really 버튼 둘 다 알약(56×48, bg-ink, 24px 돼지 + 「Really」 글자)에서
  원형 56×56 투명 버튼 + SVG 한 장으로 바꿨다. 글자가 사라진 자리는 aria-label 이 받고,
  글자와 겹치던 sr-only 는 없앴다
- 펴면 같은 크기 bg-ink 원에 접는 화살표를 둔다. 닫힘/열림 모두 56×56 이다
- 버튼에 focus-visible:rounded-full 을 더했다
- index.css 두 줄: body color #30363F → #4E5968, ::selection #ffe600 → #E4EDFB

## 왜 이렇게 했나

really-fab-blue.svg 는 파란 원판에 돼지까지 그려 둔 완성된 버튼 한 장이다.
그걸 알약 안에 24px 로 넣으면 원판 위에 원판이 겹친다. #242 에서 RainDrop3 이
「버튼 자체가 저걸로 바뀌는 걸로 생각했다」고 지적했고, 브랜드 README 도 같은 모양
(투명 버튼 + 원형 SVG, 44·56·72 중 56 이 기본)을 정해 두고 있었다.

글자를 남겼던 근거는 「그림만 두면 무엇을 여는 버튼인지 모른다」였는데, aria-label 과
옆에 뜨는 알림 풍선이 이미 그 역할을 한다. 과하게 봤다.

전역 :focus-visible 이 border-radius: 4px 를 얹는다. 알약일 때도 같은 일이 있었지만
원이 되니 동그라미에 네모 테가 그려져 눈에 띈다. 버튼 쪽 선택자(0-2-0)가 이겨서
focus-visible:rounded-full 한 줄로 되돌아간다.

::selection 은 핑크(highlight)로 가지 않았다. 재 보니 ink 5.72 는 되는데 ink2 2.46,
muted 1.59 라 선택하면 글자가 묻힌다. accent-soft 는 각각 14.04 · 6.03 · 3.91 이다.
이 두 색은 팔레트를 바꿀 때 빠뜨린 것이고, check:tokens 가 tailwind.config·DESIGN.md·
Styleguide 만 보기 때문에 잡히지 않았다.

## 남은 것 · 아는 문제

- check:tokens 가 index.css 는 보지 않는다. 박힌 색이 또 남을 수 있다
- 선택 바탕의 muted 대비 3.91 은 4.5 아래다. muted 글자를 드래그하는 경우라 그대로 뒀다

## 13:30 문진을 흐름에서 빼고, 입력 오류와 꼬리말을 정리한다

### 왜 이렇게 했나

**문진은 한 번 하면 다시 하지 않는 설정이지 판정마다 밟는 단계가 아니다.** 띠에 끼워

보여주는 일이 원래 따로였다**는 점이다 — 문진을 강제하는 쪽은 `Confirm.tsx:196`
(`to={!batchId ? '/upload' : '/interview'}`) 이고 `STEPS` 는 그리기만 한다. 그래서
띠에서 빼도 흐름이 깨지지 않는다. 띠를 그냥 두면 문진 화면에서 어느 칸도 켜지지
않아 고장난 것처럼 보이므로 그 화면만 숨긴다.

**3번과 6번이 서로 달랐다.** 개업일은 빨간 글자만 띄우고 테두리는 그대로였고,
면적 비율은 `aria-invalid` 만 걸어 둬서 화면에 아무것도 안 나왔다 — 문구 자체가
없었다. 테두리(`aria-[invalid=true]:border-deny`)와 문구를 한 상수로 묶어 두 칸이
같은 식으로 알리게 했다. 비율 문구는 「1 과 100 사이의 숫자를 적어 주세요」.

**「데이터 경계 안내」는 링크가 아니었다.** 링크 넷 옆에 같은 모양으로 서 있어서
눌리는 것처럼 보이는데 아무 일도 없었다. 갈 데를 새로 만드는 대신 뺐다 — 같은
내용이 카드내역 올리기 화면의 오른쪽 패널과 개인정보처리방침에 이미 있다.

## 14:20 회원가입의 약관·처리방침을 창으로 띄운다

- 커밋: 1efef9c (1개)
- 주요파일: Modal.tsx, Signup.tsx, Terms.tsx, Privacy.tsx

### 한 일

- `Modal` 에 `size="lg"` 를 더했다. `max-w-2xl`, 화면 높이까지, 본문만 스크롤.
  읽을 거리일 때는 창 자체에 초점을 준다. 기본값 `md` 는 그대로라 쓰던 다섯 곳은 안 바뀐다
- `Terms`·`Privacy` 본문을 `TermsBody`·`PrivacyBody` 로 빼고 시행일도 상수로 뺐다
- 회원가입의 「보기」 둘을 모달로. `<label>` 밖으로 뺐다
- 약관 본문의 처리방침 링크는 `onOpenPrivacy` 를 받으면 창을 갈아끼운다

### 왜 이렇게 했나

**「보기」를 실제로 눌러 재 봤다.** `target="_blank"` 가 걸려 있는데도 새 탭이
열리지 않고 같은 탭이 `/terms` 로 바뀌었다 — 탭 수 2개 그대로, 가입 폼은 사라졌다.
왜 `_blank` 가 안 먹는지는 밝히지 못했다. 링크가 체크박스 `<label>` 안에 있는
탓으로 보인다.

`Modal` 주석이 「되돌릴 수 없는 동작 앞에서만 쓴다」였다. 그 규칙을 바꾸는 쪽을
골랐다 — 창을 하나 더 만들면 초점 가두기·Esc·바깥 클릭·스크롤 잠금을 다시 짜야
하고, 그게 이미 다 들어 있는 것을 두고 베끼는 셈이다. 대신 크기와 스크롤을
옵션으로 더해 쓰던 다섯 곳이 안 바뀌게 했다.

**「보기」를 label 안에 두면 누를 때 체크박스까지 켜진다.** 읽어 보려다 동의한
것이 되면 안 된다. label 은 체크박스와 글자만 감싸고 「보기」는 형제로 뺐다.

**초점을 첫 요소로 보내면 문서가 중간부터 열렸다.** 약관 본문 가운데에
처리방침 링크가 있어서 브라우저가 거기까지 밀었다. 창은 `tabIndex=-1` 이라
초점을 받을 수 있고 스크린리더는 제목을 읽는다. Tab 을 누르면 그때 본문으로 간다.

처리방침 「보기」도 같이 바꿨다. 바로 옆 줄에 같은 모양으로 서 있어서 하나만
고치면 둘이 다르게 움직인다.

### 남은 것 · 아는 문제

- `target="_blank"` 가 왜 안 먹었는지 밝히지 못했다. 바꾼 코드에는 더 이상 없지만
  다른 곳에 같은 꼴이 있으면 같은 일이 생길 수 있다
- 창 안에서 Tab 을 눌러 본문 안을 도는 것까지는 확인했지만 **스크린리더로 듣지는
  않았다**
