### 한 일

- 머리말 이름은 이메일에서 @ 앞만 보인다. 이름을 누르면 내 정보, 거래, 업로드 이력(관리자는 관리자), 로그아웃 메뉴가 열린다(`AccountMenu`). 앱 머리띠와 로그인한 공개 화면 머리가 같이 쓴다. 상단의 거래, 업로드 이력 알약과 경로 표시(홈 > …)를 뺐다. 탭 제목은 그대로다
- 분류 확인에서 거래가 한 건인 가맹점은 「건별 보기」 없이 날짜만 보인다
- 문진 2번은 「직전연도 수입금액을 알고 있나요?」다. 예면 금액을 받고 기장의무는 7,500만 원 기준으로 정한다. 아니요면 간편장부, 복식부기를 기준과 함께 고르고 수입금액은 0 을 보낸다. 추계는 뺐고 직원 있음은 업종처럼 준비 중이다
- 고른 선택지를 다시 누르면 거둔다(`ChoiceGroup onClear`). 질문 답은 새 API `POST /question-responses/withdraw`로 지운다. 판정 바꾸는 이유와 한 번에 답하기 선택은 화면에서만 풀린다
- BE: 답 취소는 UserFact 새 version(`withdrawn`, V23)으로 남기고 답할 때와 같은 거래를 다시 판정한다. 서버는 같은 질문을 새 id 로 다시 내고 옛 id 는 취소한다. 답하기도 검증 전에 사용자 락을 잡는다
- 글자 버튼을 그림 버튼(`IconButton`)으로 바꿨다: 보기, 삭제, 문진 고치기, 다시 올리기, 답 바꾸기, 닫기, 빼기와 넣기, CSV, PDF, 복사, 약관 보기, 페이지 이동. 규칙은 DESIGN.md IconButton 절
- 버그 신고 화면을 가운데 한 단으로 옮겼다

### 왜 이렇게 했나

- 답을 거두면 서버가 질문을 새 id 로 다시 낸다. 제자리에 남긴 카드는 자리만 기억하고 그리는 그룹은 늘 다시 읽은 목록의 것을 쓴다. 거둔 뒤 목록을 다시 받을 때까지 선택지를 막아 옛 id 로 답해 409 가 나지 않게 했다
- 수입금액 0 은 접대비 한도를 기본 1,200만 원으로만 잡는다. 모른다는 사람에게 금액을 지어내지 않으려고 0 을 보낸다(치오 결정)
