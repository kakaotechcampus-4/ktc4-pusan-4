# 업로드 화면에서 무작위 카드내역을 바로 만든다

- 브랜치: feature/demo-random-upload
- 커밋: a7dde947..05bbe331 (2개)
- 주요파일: parser/randomSample.ts, parser/demoPool.json, scripts/build-demo-pool.ts, pages/Upload.tsx

## 한 일

- 멘토 시연용으로 「샘플 파일로 해 보기」 맨 위에 「무작위 카드내역 만들기」를 두었다. 누르면 100~300건짜리 KB 승인내역 `거래내역_<UUID>.xls` 를 바로 만들어 미리보기로 넘긴다
- 판정별 건수는 `randomCounts` 가 정한다. 확인필요는 1건부터 전체의 10%까지, 나머지는 가능 50~80%, 불가가 그 나머지다
- 생성 함수 `buildRandomSample(counts)` 는 판정별 건수를 받아 풀에서 그만큼 고른다. 승인번호는 새로 만들어 같은 계정에 여러 번 올려도 중복으로 걸리지 않는다
- 풀(`demoPool.json`, 417건)은 `scripts/build-demo-pool.ts` 가 만든다. 후보 441건을 KB 파일로 만들어 로컬 서버에 올리고 판정을 돌려 나온 판정을 거래마다 적는다. 가능 163, 확인필요 155, 불가 99
- `samples.ts` 에 주어진 행으로 KB 파일을 만드는 `buildKbDemoXls` 를 더했다. 머리는 기존 'demo' 와 같은 7~9월이다

## 왜 이렇게 했나

**판정 결과는 손으로 정하지 않고 실제로 돌려 본 값이다.** 같은 가맹점도 주말이면 판정이 바뀌고(R-311~R-314), 전자기기는 금액에 따라 갈린다. 그래서 가맹점이 아니라 날짜와 금액까지 묶은 거래 하나를 풀의 단위로 두고, 무작위 파일에서도 날짜와 금액을 바꾸지 않는다.

**답변 대기(24건)는 풀에서 뺐다.** 판정 화면은 답변 대기를 불가와 따로 센다. 풀에 넣으면 고른 불가 건수와 화면의 불가 건수가 달라진다. 질문은 확인필요 거래에서 여전히 나온다.

**평일 공휴일은 후보 날짜에서 뺐다.** 로컬 서버는 `HOLIDAY_API_KEY` 가 없어 공휴일을 평일로 판정하고 실서버는 공휴일로 판정한다. 7/17, 8/15, 8/17, 9/24~9/28 을 뺐다.

**처음에는 건수 입력칸을 두었다가 뺐다.** 멘토가 숫자를 고를 수 없게, 버튼 하나로 바로 만들게, 이름은 거래내역_UUID 로 바꾸자는 요청을 받았다. 처음 안은 이름에 판정별 건수를 적었는데 시연에서 결과가 미리 보이므로 뺐다.

## 남은 것 · 아는 문제

- 실서버에서는 돌려 보지 않았다. 실서버의 전역 가맹점 사전이나 규칙 카드가 로컬과 다르면 판정이 달라질 수 있다
- 같은 계정에서 질문에 답하면 가맹점 단위 답이 다음 업로드에 그대로 쓰여 판정이 바뀐다. 시연 계정이 답을 한 뒤로는 건수가 목표와 어긋날 수 있다
- 문진을 바꾸면(직원 있음, 자택 비율) 풀이 맞지 않는다. 그때는 `build-demo-pool.ts` 의 `CONTEXT` 를 바꿔 다시 만든다
- 불가 고유 거래가 99건이라 200건 넘는 파일에서는 같은 거래(승인번호만 다름)가 두 번 나올 수 있다
